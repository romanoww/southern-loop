# CLAUDE.md — project context

Context for anyone (human or Claude) picking this up. Written at handoff from the
chat session that built it, so the reasoning behind the non-obvious decisions isn't lost.

---

## What this is

A single-file interactive trip planner for a 192-day family trip in 2027:
**Singapore (5d) → New Zealand (78d) → Australia (74d) → Japan (35d)**.

Travelling with a **2.5-year-old**, which drives most of the content decisions:
hikes capped at ~3h and mostly under 2h, playgrounds and beaches favoured, and
the well-known walks that are too long are replaced with the toddler-viable
alternative and a note saying why.

Campervan for all of New Zealand, and Melbourne → Byron Bay in Australia.
The other Australian stops and all of Japan except the Hokkaido loop are fixed accommodation.

**Current contents:** 65 stops (1 SG / 32 NZ / 21 AU / 11 JP), 6 flights,
211 stays, 305 activities, 46 real routed road geometries.

## Repo layout

```
index.html    the entire app — Leaflet, trip data, logic, all inlined
planner.html  tiny redirect stub — bookmarkable shortcut into planner mode, no credentials
picks.json    shortlist/booking state; changes during planning
README.md     user-facing instructions
CLAUDE.md     this file
```

Private data (`private-notes.json`) does **not** live in this repo — it lives in a separate,
actually-private repo, `southern-loop-private`. See "Private tab" below.

There is no build step. `index.html` is generated by substituting a JSON blob into a
template, but the committed file is standalone and directly editable.

## Architecture: why it's one file

The app has **zero external JavaScript or CSS**. Leaflet (147KB) and its stylesheet are
inlined. This is deliberate and was arrived at the hard way — do not "clean it up" by
moving them back to a CDN.

**Reason:** iPhone users reported a blank, unclickable page. Root cause was
`cdnjs.cloudflare.com` being blocked by iOS content blockers (AdGuard, 1Blocker and
similar block it routinely). Because `initMap()` ran *before* the list rendered, one
failed CDN request killed the entire page.

Two fixes, both of which must be preserved:

1. **Content renders before the map.** `boot()` calls `renderWardrobe` → `renderSpine`
   → `renderOutbound` first, each in its own `try/catch`, and only then touches the map.
   The itinerary has no external dependencies and must never be taken down by the map.
2. **Leaflet is inlined.** Nothing to block.

Remaining network dependencies and their degradation:

| Dependency | If blocked |
|---|---|
| Map tiles (OSM) | falls back to a second tile server, then a plain backdrop with routes still drawn |
| Google Fonts | non-blocking `media="print"` trick; system fonts render instantly |
| Wikipedia photos | thumbnails become coloured initial tiles |

Everything is guarded: `mapDead` flag, `try/catch` around every map call, and
`isMobile()` never throws (it falls back to a width check if `matchMedia` is missing —
that one matters because it runs on every card click).

## Data pipeline

All data is **baked into `index.html`**. The Python scripts that generated it are not in
this repo; they lived in the authoring sandbox. If data needs regenerating, the sources are:

- **Climate** — Open-Meteo historical archive (`archive-api.open-meteo.com`), hourly,
  5 years (2022–2026), bucketed per calendar date.
- **Road routes** — BRouter (`brouter.de`), `car-fast` profile, geometry simplified with
  Douglas-Peucker at ε=0.002 (~137k points → ~4k).
- **Photos** — Wikipedia REST summary API, chosen for the *natural landmark* of each stop
  rather than the town.
- **Places** — Google Places API was used only to validate that names resolve. Links in the
  app are plain Maps *search* URLs, which self-correct if a business moves or renames.

### Climate methodology — read before changing

Temperatures are 5-year averages at **07:00, 12:00, 17:00 and 22:00**, plus the true 24h
low/high and the observed range across all sampled days.

Three real bugs were found and fixed here. Don't reintroduce them:

1. **Day/night window bug.** "Night" was defined as 18:00–06:00, but the daily minimum
   almost always falls at 05:00–06:00, and 06:00 was classed as *day*. Overnight lows read
   ~0.9°C too warm on average, up to 2.1°C. Fixed by reporting the **true 24-hour** min/max.
2. **Tongariro elevation.** Whakapapa coordinates landed on a grid cell at **1799m** (the
   volcano slopes) rather than the village at ~1119m — readings were ~5°C too cold, showing
   sub-zero nights that don't exist. Moved to National Park Village (model 1043m).
3. **Catlins placeholder coordinate.** A made-up centroid inland in the forest, with no road
   access. Broke both the climate reading *and* routing (Dunedin→Catlins came out as 5h32
   instead of ~2h). Moved to Papatowai.

**Lesson:** when adding a stop, always check the model elevation Open-Meteo returns against
the real settlement elevation. More than ~250m out means roughly 1.6°C of error.

### Drive times

BRouter *distances* are reliable; its *times* are not — it picks shorter-but-slower back
roads and stacks heavy penalties on winding rural sections. Times shown are a **blend** of
the routed time and a distance/speed model (NZ 75 km/h, AU 85, JP 70), validated against ten
known real durations to **~7% mean error**. They run slightly conservative, which is the right
direction with a toddler. Nelson Lakes→Tākaka and Punakaiki are the least certain.

## App structure

Single inline `<script>`. Key globals:

- `DATA` — the whole trip; keys `sgLegs / nzLegs / auLegs / jpLegs`, `flights`,
  `roadRoutes`, `wardrobe`, `mapUrls`, `summary`
- `currentTab` — `sg | nz | au | jp | fl | bk`; `LEG_SOURCE` maps the first four to leg arrays
- `picks` — `{ "tab|stop|kind|item": "pick" | "booked" }`, `kind` ∈ `stay | act | flight`
- `editMode` — planner vs viewer

Layout is a **flex app shell** using `dvh`, with only `.listPane` scrolling internally.
Do not switch to `position:fixed` + `vh` — that was tried and broke on mobile, because the
viewport resizes as the address bar hides.

### Viewer vs planner

One file, two modes. Planner unlocks when a GitHub token is present, or via `?edit=1` (or
`planner.html`, which just sets the same flag and redirects), or by tapping the page title
three times. This is **presentation only** — the actual protection is that repo writes need
the token, which lives only in the user's browser and is never in the file. `planner.html`
carries no credentials itself; it exists so the owner has a clean bookmark instead of typing
`?edit=1`. It does **not** gate the Private tab — that's tied to `ghReady()` (a real token),
not this flag, since a viewer forcing planner mode via any of these three routes still has no
token and must not see it.

### Sync

Local-first. Writes go to `localStorage` immediately; `picks.json` is fetched on load and the
**newer timestamp wins**. Saving commits `picks.json` via the GitHub contents API (GET for the
SHA, then PUT). Single writer by design — Steven edits, everyone else reads.

### Private tab: a second, genuinely private repo

This repo (`southern-loop`) is **public** (`visibility: public`, confirmed via the API) —
GitHub Pages on a personal plan serves it to anyone regardless of any UI gating, and even
without Pages, a public repo's files are readable via the web UI, `raw.githubusercontent.com`,
or a plain clone. A client-side-encrypted file here was the first design (see git history if
you need it) but a genuinely private companion repo is simpler and has no passphrase-loss risk,
so that replaced it.

**`southern-loop-private`** is a separate, actually-private GitHub repo holding
`private-notes.json` in **plain JSON** — no encryption needed, because GitHub's own repo
permissions do the access control. It has no Pages site and is never fetched as a static file;
every read and write goes through the authenticated Contents API
(`api.github.com/repos/{owner}/{repo}/contents/...`), gated by a token whose holder must be a
collaborator on that repo. Steven and his wife each add their own fine-grained PAT, scoped only
to `southern-loop-private`, in their own browser — same one-token-per-device model as `gh`
(the main config), just a second, independent `ghPriv` config (`southernLoop.ghpriv.v1`)
pointed at a different repo. Losing a token is a GitHub-account problem now, recoverable the
normal way — not a self-inflicted, unrecoverable one.

**Tab visibility** is `editMode || ghPrivReady()` — looser than the encrypted version was,
deliberately: since the real protection moved to GitHub's server-side repo permissions, hiding
the tab is back to being presentation-only (consistent with how `editMode` already works
everywhere else), and someone needs *some* way to reach the "connect your repo" form the first
time before `ghPrivReady()` can ever be true.

State machine in `renderPrivPane()`: `setup` (no `ghPriv` credentials, or the fetch needs them)
→ `loading` → `ready` (loaded — including a fresh empty state on a `404`, meaning the file
doesn't exist yet) → `error` (auth failure or network issue — shows a specific "check you're a
collaborator" message rather than silently treating it as "no data"). Saving reuses the
GET-SHA-then-PUT pattern from `pushToGitHub()`, against `ghPriv`'s repo instead of the main one.

Structured fields: `documents` (passport/IDP — label, number, expiry), `refs` (booking
references — label, code), `budget` (total/spent/currency/notes), and a freeform `notes`
catch-all. Row inputs use inline `oninput` handlers that mutate `privData` directly rather than
re-rendering on every keystroke — a full re-render on each character would drop input focus.

## Testing

18 Node + jsdom suites (`runtest*.js`) lived in the authoring sandbox. They stub Leaflet, drive
real DOM events and assert on the result. They caught several genuine bugs, including
`Element.scrollTo` being unsupported in older Safari and pin taps selecting the card underneath.

If you add tests here, the important scenarios are:

- **Leaflet completely blocked** — cards, links and filters must all still work
- **Viewer vs planner** — no edit buttons or save bar in viewer mode
- **Real Leaflet with all network blocked** — map must still initialise
- Tab switching, both filter groups, and both directions of map↔list selection

Note: jsdom reports `document.readyState === 'loading'`, so tests must dispatch
`DOMContentLoaded` manually for `boot()` to run.

## Conventions

- **Honesty over polish.** Estimates are labelled as estimates; the footnote states the
  methodology and names the least reliable legs. Keep that.
- **Toddler constraint is a hard filter,** not a preference. Anything over ~3h walking needs
  an explicit note about why it's included.
- **Seasonality matters and is called out** — east-Australian humpbacks build through June, so
  the mid-May NSW stops are flagged as early and Byron's operators mostly start ~1 June.
- **Never commit a token.** The only `github_pat_` string in the file is an input placeholder.
- Content edits go in the `DATA` blob; behaviour in the script below it.

## Known open items

- Flight times for four of six legs are `TBC` — only the two Singapore Airlines flights are booked.
- Nothing is booked yet; `picks.json` is empty.
- **Obihiro → Hakodate is a ~5h drive**, the longest single day in Japan. It exists because the
  Shinkansen only reaches Hakodate. Alternative is returning the van at New Chitose and taking
  the limited express, which is slower overall.
- **Japan needs a 1949 Geneva Convention IDP.** The ANWB issues both that and the 1968 Vienna
  version; the 1968 one is **invalid** in Japan.
- **NZ freedom camping needs a Green Warrant** (mandatory since 7 June 2026). 12 self-contained
  sites in the app assume one.
- Offline packaging (service worker + manifest) was discussed and deliberately skipped —
  coverage was judged good enough.
